# 要件定義

## 目的と想定ユーザー
PokeAPI (https://pokeapi.co) を引くデスクトップ図鑑アプリ。ポートフォリオとして、次の流れを一通り示す。

- MyGo の native UI によるデスクトップアプリ
- 要件からテスト、実装へとつながる開発プロセス (`docs/development.md`)
- GitHub Actions による CI と、macOS 向けの配布

想定ユーザーは、ポケモンを名前で引いて基本情報を見たい人と、このリポジトリを読む人 (レビュアーや採用担当者)。

## 機能要件 (v0.1.0)
受け入れ条件は `ui.NewTester` の受け入れテスト、または単体テストで確かめる。テスト名に要件の ID を入れる (`docs/development.md` を参照)。

### FR-1: 名前で検索する
- 検索ボックスに文字を入れると、名前に部分一致するポケモンが結果リストに出る
- 大文字と小文字は区別しない (`PIKA` で `pikachu` がヒットする)
- 絞り込みは入力のたびにその場で行う。検索ボタンはない
- 検索ボックスが空なら、全件を図鑑番号順に並べる
- 名前の一覧は初回起動時に取得してディスクにキャッシュし、2 回目以降の起動ではキャッシュを使う
- 結果リストの各行は、図鑑番号と名前を 1 行で表示する。番号は、フォルム違いの `#10196` のような 5 桁でも折り返さない
- 選択中の行の番号は、名前と同じ色 (テーマの `AccentText`) にする。灰色の番号が選択色の上で読めなくならないようにする

### FR-2: 詳細を表示する
- 結果リストの行を選ぶと、詳細ペインに次の項目を表示する
  - スプライト画像 (詳細のテキストを先に出し、画像は取得でき次第表示する。画像の取得に失敗しても詳細は表示し、画像の場所には代替表示を出す)
  - 名前と図鑑番号 (`#025` の形式)
  - タイプ (1〜2 個)
  - 種族値 6 項目 (HP、こうげき、ぼうぎょ、とくこう、とくぼう、すばやさ)。数値とバーで表示する
  - 種族値の合計 (`Total 534` の形式)
- 詳細ペインの見た目
  - 上部のヘッダー (スプライト、番号、名前、タイプ) は、1 番目のタイプの色の帯にする。タイプ名ごとに固定の色を持ち、未知のタイプは中立色にする
  - タイプのバッジは、そのタイプの色を背景にし、文字色は背景に対してコントラスト比 4.5:1 以上になる白か黒にする
  - 種族値は 2 列に並べる (ラベルと大きな数値、その下にバー)
- キーボードだけでも操作できる (上下キーで行を移動し、Enter で選択)

### FR-3: 状態を表示する
- 名前の一覧や詳細を取得している間は、読み込み中の表示を出す
- 取得に失敗したらエラーメッセージと「Retry」ボタンを出す。押すと同じ取得をやり直す
- 検索結果が 0 件なら「No Pokémon found」と表示する

### FR-4: 古い結果を捨てる
- 詳細を取得している途中で別の行を選んだら、前の取得結果は表示しない。可能なら前の取得をキャンセルする
- ウィンドウを閉じたら、実行中の取得はすべてキャンセルする

### FR-5: 説明文を表示する
- 詳細ペインのヘッダーと種族値の間に、図鑑の説明文 (PokeAPI `/pokemon-species/{id}` の `flavor_text_entries`) を表示する
- 英語 (`language.name == "en"`) の、配列で最後のエントリを使う。改行とフォームフィードは空白 1 つにまとめる
- species の ID は `/pokemon/{name}` の `species.url` から得る (`#10196` のようなフォルム違いは、図鑑番号と species の ID が違う)
- 詳細のテキストを先に出し、説明文は取得でき次第表示する。取得に失敗した場合と、英語のエントリがない場合は、説明文の欄を出さない。詳細は通常どおり表示し、エラー表示にはしない
- 別の行を選んだら、前の説明文の取得結果は表示しない (FR-4 と同じ)
- 取得した説明文は、メモリとディスクに無期限でキャッシュする

## 非機能要件
| 区分 | 要件 |
|---|---|
| 性能 | 一覧がキャッシュ済みなら、キー入力から結果リストの更新まで 100ms 以内 (約 1,300 件の絞り込み) |
| 通信 | HTTP のタイムアウトは 10 秒。すべての取得を `context` でキャンセルできるようにする |
| Fair use | 同じリソースを繰り返し取得しない (メモリとディスクにキャッシュする) |
| キャッシュ | 置き場所は `os.UserCacheDir()/pokedex`。名前一覧の有効期限は 7 日。詳細は無期限 (内容がほぼ変わらないため) |
| オフライン | キャッシュにあるものは表示する。キャッシュにないものは FR-3 のエラー表示にする |
| プライバシー | テレメトリは送らない。外部通信の相手は pokeapi.co と画像の取得先だけ |
| 対応 OS | macOS (arm64)。Windows は v0.1.0 の範囲外 |
| 配布 | アドホック署名した dmg と SHA-256 のチェックサムを GitHub Release に添付する (下書き → ユーザーが公開) |
| UI の言語 | 英語 |
| 品質 | `internal/pokeapi` と `internal/app` のテストカバレッジは 80% 以上。テストは外部通信しない (`httptest` や fake を使う) |

## v0.1.0 の範囲外 (今後の候補)
- 日本語名の表示と検索 (`/pokemon-species/{id}` の `names`)
- お気に入り
- タイプでの絞り込み、進化の表示
- Windows 対応 (exe の zip を想定。MyGo は cgo 不要なので Linux runner でクロスビルドできる見込み。実機での確認が必要) (Issue #3)
- macOS の universal バイナリ
- コード署名と公証 (notarization)

## 決定事項
- 詳細ペインのデザイン (2026-10-18): ヘッダーをタイプ色の帯にし、種族値を 2 列の大きな数値とバーにする。結果リストは 260 の幅にする。バーは MyGo の `Progress` を使うため、色はテーマのアクセント色のまま (`Progress` は塗りの色を変えられない)。帯の色は半透明にして背景に重ね、ライト / ダークのどちらでも文字が読めるようにする。
- LICENSE は MIT (著作権者 `Naoya.Omi`)。アプリには、依存ライブラリのライセンス表示を `resources/THIRD_PARTY_NOTICES.txt` として同梱する (BSD / Apache の表示義務のため)。依存から生成し、CI のテストで古さを検出する。
- スプライトは `pokeapi.Client` が PNG のバイト列で取得し、`os.UserCacheDir()/pokedex/sprites/<図鑑番号>.png` とメモリにキャッシュする (無期限)。UI が `ui.DecodeBitmap` で描画用に変換する。取得先は API の `sprites.front_default` の URL (PokeAPI のスプライトリポジトリ)。
